# 留影 Afterlight

> 个人摄影叙事策展智能体 · 2026 Qoder 高校创造力大赛

上传一组照片，六个职责清晰的智能体协作——素材管家 → 审美筛选官 → 主题发现官 → 叙事编剧 → 布局设计师 → 策展质检官——
从"哪些照片值得留下"开始，发现视觉主题、组织叙事、生成网页影展并质检，最终得到一场**可浏览、可修改、可分享**的个人影展。

**核心理念：AI 提出一种观看方式，最终审美决定权交还摄影者。**

产品与技术规格见 [`留影 Afterlight_项目设计文档.md`](./留影%20Afterlight_项目设计文档.md)。

## 快速开始

环境要求：**Node.js ≥ 24**（内置 `node:sqlite`，无需原生编译）、npm。Windows / macOS / Linux 均可。

```bash
npm install
cp .env.example .env        # 可选；默认 demo 模式，无需任何 API Key
npm run dev                 # http://localhost:3000
```

打开首页 →「先看一个例子」立即载入 24 张示例照片并跑通全流程；或「开始策展」上传自己的照片。健康检查：

```bash
curl http://localhost:3000/api/health
# { "ok": true, "mode": "demo", "db": "ok", "sharp": "ok", "version": "0.1.0" }
```

- 端口冲突：`npm run dev -- -p 3001`。
- 数据落在 `data/`（SQLite + 原图），已 gitignore；请勿放在 OneDrive 等同步目录。
- **正式演示 / 比赛运行**：先 `npm run build`，再 `npm start`（生产模式）。不要与 `npm run dev` 同时运行、共享同一份 `.next`。
- `next.config.ts` 已正式配置 `devIndicators: false`：开发与生产界面均无 Next.js N 角标；真实错误仍照常出现在控制台与服务端日志（未用 CSS / node_modules 遮挡）。

## 运行模式

- **`demo`（默认）**：无需 API Key。示例照片命中内置预设分析；自有照片走本地确定性规则（清晰度/亮度/pHash/主色 + 启发式筛选、主题、叙事）。完整可演示，页面常驻诚实徽章；全程零外部请求。
- **`ai`**：真实模型模式。v3 阶段 C/D/E 已接通视觉、选片、主题、叙事四个真实 adapter，并完成 Mock 全流程验证；共用授权、预算、缓存及调用记录，不静默回退 Demo。阶段 F 已加入模式/授权/连接状态界面、独立确认的固定文字与合成图探测；默认模式不会自动授予外发授权。选片/主题确认门、must_keep、编辑与锁定继续生效。**已进入阶段 G 的离线安全准备；真实服务商联调与质量验收仍待明确照片、服务商和调用上限后执行**。

通过 `.env` 的 `AFTERLIGHT_MODE` 设置全局默认，创建影展时也可单独选择。

### 作者配置真实模型（工程已接通，真实联调待授权）

**比赛范围**：只交付本机完整 AI 演示，不新增登录系统或每用户限额，不开放公网；保留现有费用预算和照片授权。DeepSeek 官方配置与非思考模式适配见 [`docs/ai-setup.md §3.1`](./docs/ai-setup.md#31-deepseek-本地比赛配置)，真实 Key 只在本机填写，文档和 Mock 通过不代表真实联调通过。

1. `cp .env.example .env.local`，按注释填写 `AFTERLIGHT_MODE=ai`、`AI_API_KEY`、`AI_BASE_URL`、`AI_VISION_MODEL` 等字段（`AI_TEXT_MODEL` 可省略，自动回退视觉模型），详见 [`docs/ai-setup.md`](./docs/ai-setup.md)。
2. 重启服务生效：dev 用 `npm run dev`，比赛用 `npm run build && npm start`。
3. 创建页/素材页可展开「AI 使用说明与连接状态」。状态读取不调用模型；单独确认后测试固定文字和合成图片，最多 2 次请求，不使用个人照片，不自动重试。文字通过不代表视觉可用，双通过不保证真实质量。
4. 素材页可授权或撤销照片外发，运行中仍能撤销后续请求；切换模式取消旧授权和选片确认，需重新分析，旧作品保留。未配置/未授权仍可创建与上传。
5. 运行边界：**Key 只从服务端环境读取**，不应出现在页面、bundle、接口、日志、导出或 URL；外发仅在影展同时满足 mode=ai、勾选外部处理授权、预算未超限时发生；非 localhost 服务商地址强制 HTTPS；超时/限流/余额按分类处理，已保存作品不受影响。
6. dev/start 默认绑定 `127.0.0.1`，API 写入口要求回环地址与同源 Origin，`public` 模式拒绝写入。该保护不等于公网认证，当前仅支持本地运行。

## v2.1 体验升级（任务书 §19 专项）

- **顺畅向导**：上传后点「分析照片并推荐选片」，ingest→select 完成即自动进入确认选片；确认后自动发现主题；选主题后一键生成并直达内容页。自动前进绑定本次 workflow 与输入 revision——HTTP 202 不算完成、历史成功不误跳、刷新不重复启动、主动离页不被拉回。
- **确认门**：选片确认（含暂缓照片的一次性处理选择）与主题选择都由用户显式决定，系统不跳过。
- **批量与撤销**：保留/暂缓/移除三组均支持多选、全选、反选、批量决定与恢复 AI 建议；服务端单事务 + revision 冲突检测 + request_id 幂等；must_keep 默认受保护，最近一次批量可撤销。
- **自动放映**：浏览页与「一键放映」按章节节奏自动滚动，暂停/继续/三档速度/上一段下一段/从头播放/全屏；手动滚轮立即接管；切后台自动暂停；直接打开链接默认静止。
- **离线导出放映**：单文件 HTML 内嵌同一套放映路线与固定控制器（CSP 脚本哈希，无 eval、无外部依赖），断网可播放；禁用 JS 仍可读完整作品。
- **普通用户语言**：进度默认显示「正在读取照片 / 正在推荐选片…」，技术名与输入输出 JSON 留在折叠详情；历史折叠为「历史处理记录」；网络失败显示重试横幅，不误报业务空态。

逐项验收（UX01–UX29 通过/未测 + 证据）见 [`docs/upgrade-acceptance.md`](./docs/upgrade-acceptance.md)。

## 三分钟比赛演示脚本（v2.1 流程；旁白沿用设计文档 §18）

> 正式比赛用生产运行：`npm run build` 后 `npm start`。以下操作在 v2.1 向导中一气呵成，无需寻找后台阶段。

### 0:00—0:20：提出问题

展示一组 24 张照片。

旁白：

> "我们现在拍下的照片越来越多，但相册只能告诉我们它们是什么时候拍的。它很少告诉我们：这些照片放在一起，究竟在讲什么。"

### 0:20—0:45：上传照片，一次点击

将 24 张校园或旅行照片拖入系统（或点「先看一个例子」），点击主按钮**「分析照片并推荐选片」**。
展示逐张缩略图进度；分析完成后页面**自动进入确认选片**，不需要找步骤 2。

### 0:45—1:05：确认选片（可批量）

展示系统从 24 张照片中推荐保留 17 张。在「暂缓」组演示多选/全选 → 批量保留；点击一张被暂缓的照片：

> "它有轻微失焦，但提供了整组唯一的低角度视角，所以系统没有直接删除，而是把最终决定留给我。"

点主按钮**「确认选片，发现主题」**（如有暂缓照片，先一次性选择本次排除/全部保留）。

### 1:05—1:30：主题发现

系统展示三个主题：

- 窗与背影；
- 反复出现的蓝色光线；
- 人物与空间之间的距离。

点击主题"人物与空间之间的距离"，展示代表照片和证据，点**「用这个主题生成影展」**，自动进入内容生成进度。

旁白：

> "我原本以为这是一组校园照片，但系统发现，我一直把人物放在画面边缘，让空间先于人物出现。"

### 1:30—1:55：生成叙事

展示影展标题《在光线转弯之前》和三个章节：

- 进入；
- 经过；
- 留下。

强调文案来自照片的可观察关系，不编造人物经历。点**「确认内容，查看版式」**。

### 1:55—2:25：一键放映

在版式页点**「一键放映 ▶」**：首图停驻、章节留白、照片按节奏自行展开，无需滚轮。
中途点「暂停」讲一句话，再「继续」；切到「快速」档展示速度控制。让评委真正看到最终作品，而不是后台页面。

### 2:25—2:45：人机共同策展

点「手动浏览」接管，删除一张照片或把一张照片拖到第三章，点**「更新影展」**精确重跑受影响阶段，再次放映反映修改。
（可选收尾：导出 HTML，当场断网打开，离线继续放映。）

旁白：

> "AI 提出了观看方式，但最后的选择仍然属于我。我的修改会影响后续叙事和布局，而不是被系统悄悄覆盖。"

### 2:45—3:00：总结

> "留影 Afterlight 不是帮你管理照片，而是帮你发现：你到底在反复拍什么，以及这些照片可以怎样被观看。"

**任意一次需要手动修改数据库或重启服务即判失败。**

| 轮次 | 全流程耗时 | 改库/重启 | 结果 |
|---|---|---|---|
| 第 1 次 | 13.8s | 无 | 通过 |
| 第 2 次 | 10.0s | 无 | 通过 |
| 第 3 次 | 13.0s | 无 | 通过 |

> 主题「人物与空间之间的距离」、筛选 24→17（17 keep / 4 hold / 3 remove）；删除一张后 `stale_from=motifs`，
> 一键重跑 motifs→qa，布局由 16 个 section 重新生成为 18 个，预览即时反映修改。全流程远低于 3 分钟上限。

> 演示可靠性保障：每次「先看一个例子」创建全新影展 id，三次互不碰撞；首页「重置演示数据」一键删除旧示例影展（文件 + 行）。

```
│   │   ├── demo/seed     # 创建全新示例影展
│   │   └── files/        # 原图/缩略图仅经此本地路由（?variant=thumb|original）

public/demo/photos/       # 24 张 AI 生成示例照片（提交 git，新克隆即可演示）
```

**核心保证**

- **阶段图**：`ingest → select → [门：确认选片] → motifs → [门：awaiting_theme_choice] → narrative → layout → qa`。
  路由创建首个 run 行后立即返回（202），后台异步执行；内存 + DB 双重并发守卫（409）；自动前进只认本次 workflow + 输入 revision。
- **失败隔离**：某阶段失败 → `stage_failed` + `failed_stage`，之前各阶段结果不动，下游标 skipped，可从失败阶段幂等重试。
- **用户编辑不被覆盖**：照片决定列分离（`ai_decision` / `user_override`，`must_keep` 只能由用户写入，结构上不可被 Agent 产出）；
  文案/结构经 `merge.ts` 在重跑后回放用户编辑与锁定；每次完整管线成功 + 破坏性操作前写版本快照，可回滚（含编辑/锁定）。
- **局部重跑**：编辑后只设 `stale_from`，由「应用修改并重新生成」按钮按矩阵精确触发，不自动重跑、不悄悄覆盖。
- **布局设计师与质检官是纯确定性规则引擎**，两模式一致；叙事过 `credibility.ts`（禁断言/保留表达/字数）。

## 导出

- **静态 HTML**：`renderToStaticMarkup` + 内联 CSS，图片经 sharp 降到 ≤1600px / q80 嵌 base64，单文件可独立打开分享，**绝不嵌原图**。
  v2.1 起内嵌放映：路线 JSON 放在不执行的 `<script type="application/json">`，控制器为固定脚本并以 CSP `script-src 'sha256-…'` 白名单放行（无 unsafe-eval、无 CDN）；
  断网可播放/暂停/调速；禁用 JS 时静态覆盖层保证完整作品可读；打印自动隐藏控件并暂停。
- **结构数据（高级导出，JSON 包）**：schema_version + 全量 meta / 分析结果 / user_edits / 最新版本快照（导入不在 MVP）。
- **打印**：浏览页 print CSS（白底、章节分页）；PDF 明确延后。

## 数据来源与隐私

- **示例照片为 AI 生成**（《在光线转弯之前》：窗/背影/冷光/走廊/反光…），非真实拍摄；页面常驻「演示模式」徽章，不伪装实时模型推理。
- 原图默认本地保存（`data/uploads/`），**不上传公开服务、不在 `public/` 下暴露**，仅经本地 `/api/files` 路由访问；未授权 URL 不可读取原图。
- 不默认保留 GPS 与相机信息（按 `allow_exif` 过滤）；公开前提示人工检查人脸/车牌/地址。
- 不编造人物身份、私人关系或经历；叙事只基于可观察视觉关系、EXIF 与用户主动提供的背景。
- 提供删除当前影展与所有本机图片的入口；首页可一键重置演示数据。
- 外部 AI 模式默认关闭，原图本地优先；仅在用户明确选择时才允许外部模型分析。外发的是转正、限长边、JPEG 重编码且去元数据的分析副本（≤1MB，默认长边 1280）；副本只在服务端内存中使用，不写磁盘、数据库或日志。

## 已知限制（MVP）

- 不做账号/社交/视频/自动修图/云端永久存储。
- 一组照片、两个模板、三个章节。
- 四个真实 adapter 已接入，但 Mock 不代表真实服务商兼容性、审美质量或全面抗注入能力；主题精确重名拒绝不等于语义去重，事实校验仍有规则边界。人脸/车牌不做自动检测。

- 缓存仍按 workflow 隔离；跨 AiClient 合并仅限同进程、同数据库对象/transport、等值配置与相同请求，不是多进程去重；新 workflow 仍可能重新发送成功照片并消耗同一任务额度。公开部署权限/限流未实现。
- 进度用 800ms 轮询（非 SSE），演示可靠性优先。
