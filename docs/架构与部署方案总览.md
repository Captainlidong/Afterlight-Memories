# 留影 Afterlight — 架构与部署方案总览

> **本文档用途**：向 Qoder 完整说明本作品（2026 Qoder 高校创造力大赛参赛项目「留影 Afterlight」）的部署方案全貌——包括**后端部署在作者自有腾讯云服务器**上的完整计划。Qoder 在本方案中负责静态展示层的部署；后端部署由作者本人执行。生成时间：2026-11-22，作者：Captainlidong。

---

## 1. 作品概述

「留影 Afterlight」是一个个人摄影叙事策展智能体：访客上传一组照片，系统经过六道智能体工序（素材管家 → 审美筛选官 → 主题发现官 → 叙事编剧 → 布局设计师 → 策展质检官）生成一场可放映、可导出的个人影展。核心原则：**AI 提出观看方式，最终决定权属于摄影者**（两道用户确认门贯穿流程）。

技术形态：Next.js App Router 全栈应用，运行时依赖 Node 24（内置 node:sqlite）、sharp（图片处理）、DeepSeek API（真实 AI 策展，OpenAI 兼容格式）。

## 2. 为什么采用「后端自托管」的分离架构

大赛要求作品通过 Qoder 部署获得 Qoder Sites 公网链接（评委点开即可访问）。经核查，Qoder Sites 的托管形态是**静态页面 + 边缘函数 + 平台数据库/存储**，不提供 Node 长驻服务器运行时——而本作品的创作层包含实时 AI 代理（付费 DeepSeek 接口）、SQLite 数据库、sharp 图片处理与访客会话隔离等长驻服务能力。

因此采用**三层组合架构**：

| 层 | 承载平台 | 内容 | 部署者 |
|---|---|---|---|
| **静态展示层** | Qoder Sites | 产品落地页 + 示例影展完整可玩版（离线导出 HTML，自包含放映） | Qoder（用 Qoder 的 Sites 功能部署） |
| **实时创作层** | **作者自有腾讯云服务器** | 完整创作流程：上传 → 真实 AI 策展 → 两道确认门 → 放映 → 导出（含匿名会话隔离与 AI 额度约束） | **作者本人**（本方案第 4 节） |
| **作品帖** | 天池赛题页论坛 | 自我介绍 / 作品 / 为什么做 / 怎么用 / 怎么用 Qoder 做的 + Qoder 账号 | 作者撰写 |

这样分层的原因：

1. **合规**：评委点开 Qoder Sites 链接即可看到能玩的作品（示例影展完整可玩，纯静态托管在 Qoder 上）
2. **能力**：实时 AI、数据库、图片处理等长驻服务在自有服务器上完整保留，无功能阉割
3. **安全**：DeepSeek API 密钥只存在于作者自有服务器的环境变量中（不进 Qoder 平台、不进 Git、不进任何上传产物）
4. **成本可控**：访客 AI 体验受三层额度约束（见第 5 节），最坏日成本约 $0.10

## 3. 创作层服务器详情（作者自有腾讯云）

### 3.1 服务器

| 项 | 值 |
|---|---|
| 平台 | 腾讯云 Lighthouse（轻量应用服务器），广州六区 |
| 公网 IPv4 | 〈从略：固定公网 IP，不入公开仓库〉 |
| 规格 | 2 核 / 2GB 内存 / 50GB SSD / 5Mbps 峰值带宽 / 400GB 月流量 |
| 系统 | OpenCloudOS 9（预装宝塔 Linux 面板 13.0.0） |

### 3.2 部署物

`afterlight-server.tar.gz`（约 69MB，已完成构建与依赖预装）：

- `.next/` 生产构建产物 + `public/` 静态资源
- `node_modules/`（**linux x64 版**依赖，云端无需再安装构建工具）
- `seed/` 空种库（已应用全部数据库迁移的 SQLite 骨架，首次启动复制到数据目录）
- `start.sh` 启动脚本（前台运行，绑定 0.0.0.0:3000，支持 systemd 托管）

### 3.3 服务器端环境变量

| 变量 | 值 | 说明 |
|---|---|---|
| `AI_API_KEY` | 作者的 DeepSeek 密钥 | **仅存于服务器上的 `.env.server` 文件**（权限 600），不进部署包、不进 Git、不出现在日志与前端 |
| `AI_BASE_URL` | `https://api.deepseek.com` | start.sh 默认值 |
| `AI_VISION_MODEL` | `deepseek-flash` | start.sh 默认值 |
| `AFTERLIGHT_PUBLIC` | `1` | 启用访客匿名会话与额度约束 |
| `AFTERLIGHT_DISK_WATERMARK_MB` | `2048` | 上传总量水位（服务器 50GB 盘） |
| `AI_REVIEW_WINDOW` | `2026-12-01~2026-12-07` | 大赛评审期窗口：期间真实 AI 全天候开放（额度约束仍生效） |

### 3.4 部署步骤（作者执行，详见 deploy-package/腾讯云部署清单.md）

1. 腾讯云控制台防火墙放行 TCP 3000
2. 上传 tar.gz 至 `/opt`，安装 Node 24（npmmirror tarball）
3. 解压至 `/opt/afterlight`，创建 `.env.server` 填入密钥
4. 创建 2GB swap（服务器内存已占用较多，防 OOM）
5. 注册 systemd 服务（开机自启、崩溃自动重启）
6. 验证：本机 curl 健康检查 → 浏览器访问 `http://<服务器IP>:3000` → 创建影展 → 真实 AI 体验 → 放映 → 导出

## 4. 访客体验与安全设计

### 4.1 匿名会话（无登录）

访客打开站点自动获得匿名会话 Cookie（HttpOnly + SameSite=Lax），影展数据绑定会话——**互相隔离**：每个访客只看到自己创建的影展。无注册、无密码、无账号概念；会话即临时身份，Cookie 丢失等同换新会话。

### 4.2 数据生命周期

- **滑动过期 1 小时**：最后一次活动后 1 小时，该会话的影展与上传图片成套删除（运行中的任务受保护）
- **双重保险**：平台实例重启本身也会清空数据
- 首页与素材页明确提示访客：「体验数据为临时数据，请及时导出保存」

### 4.3 AI 额度三层约束（防止额度被刷）

| 层 | 限制 | 说明 |
|---|---|---|
| 会话层 | 每会话 **1 次**真实 AI 体验 | 首次启动 AI 分析即锁定；同影展重试不重复消耗；用完可降级使用本地演示模式（不限次） |
| 全局层 | 每日 **10 次** AI 体验 | Asia/Shanghai 日界；防「换 Cookie 刷次数」的总闸 |
| 单影展层 | AI 分析照片 **≤10 张** | 超出拒绝启动并提示精选 |

**最坏日成本估算**：10 次体验 × 约 16K 输入 + 4K 输出 token ≈ $0.10/天（DeepSeek 峰值价）。

### 4.4 DeepSeek 空闲时段调度与大赛评审期

**大赛评审期（12 月 1 日 – 12 月 7 日）**：评委初筛期间真实 AI **全天候开放**，不受空闲时段限制（每日体验名额仍然有限）。评审期结束后自动恢复空闲时段约束。


除大赛评审期外，真实 AI 体验**仅在北京时间空闲时段开放**：

- **高峰（拒绝新体验启动）**：周一至周五（不含中国法定节假日）9:00–12:00、14:00–18:00
- **空闲（可用）**：其余全部时段，含周末与法定节假日全天
- 法定节假日由环境变量 `AI_PEAK_HOLIDAYS` 维护日期列表，作者每年更新；未维护时按普通工作日保守处理
- 拦截范围：仅拦「新 AI 体验启动」；已开始影展内的重试放行；Demo 模式（本地规则引擎）不受影响
- 界面提示：高峰时显示「高峰时段暂不可用，预计 xx:xx 恢复」，空闲时显示「当前为 DeepSeek 空闲时段，可体验真实 AI 策展」

## 5. Qoder 在本方案中的职责边界

**Qoder 负责**：使用 Qoder 的 Sites 功能部署静态展示层（`index.html` 落地页 + `demo-exhibition.html` 示例影展离线版，均为纯静态文件、无构建、无环境变量、无密钥），部署后自查验收（落地页渲染 / 示例可放映 / 跳转链接可达）。

**Qoder 不负责 / 不要触碰**：

- 作者自有服务器上的创作层（已由作者按腾讯云部署清单自行完成）
- DeepSeek API 密钥（只存在于作者服务器）
- 实时 AI 的调用与额度逻辑（作品内置，运行于创作层）

## 7. 常见问题

**Q：为什么不做登录系统？**
作者产品定位为本地优先的个人工具，公网体验采用匿名临时会话（无注册、无身份），配合额度约束与数据过期已足够；引入登录超出比赛交付范围。

**Q：为什么创作层不部署到 Qoder Sites？**
Qoder Sites 不提供 Node 长驻服务器运行时，而创作层需要 SQLite、sharp 与实时 AI 代理（详见第 2 节核查结论）。

**Q：访客体验会消耗作者的钱吗？**
会，但有三层封顶（每会话 1 次 / 每日 10 次 / 单影展 10 张照片），最坏日成本约 $0.10，且高峰时段自动关闭。

**Q：访客能看到别人的影展吗？**
不能。影展绑定匿名会话，跨会话访问一律 404；数据 1 小时后自动成套删除。

**Q：示例影展为什么能离线放映？**
作品内置「离线导出」能力，可将一场影展导出为单文件自包含 HTML（图片 base64 内嵌 + 放映脚本内置），这正是 Qoder Sites 上示例影展页的实现方式。
