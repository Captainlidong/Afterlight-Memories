# 留影 Afterlight 公网匿名会话版 — 设计文档（作者已确认，2026-11-22）

> 目标：满足大赛"Qoder Sites 公网完整功能"要求——访客可完整体验「上传 → AI 策展 → 放映 → 导出」，同时解决隐私可见、数据堆积、AI 额度三大公网问题。

## 已确认决策（作者 2026-11-22）

1. 过期方式：**滑动 1 小时**（最后活动后 1 小时清理）
2. AI 体验影展照片上限：**10 张**
3. 体验次数用完：**降级可用 Demo 模式**（本地规则不限次，界面明确标注）
4. 公网站**不放公共影展**：访客只看到自己的创作；首页=产品介绍+开始策展+我的影展（本会话）

## 0. 核心原则

## 0. 核心原则

- **无登录**：匿名会话 Cookie 即临时身份，无注册、无密码、无账号概念。
- **体验完整**：真实 DeepSeek 全流程可用，但受三层额度约束。
- **自动消亡**：访客数据 1 小时滑动过期，平台重启亦清空；提示访客及时导出。
- **本机零变化**：所有新机制仅在公网开关开启时生效；本机版行为、数据、测试全部不变。

## 1. 匿名会话层

| 项 | 设计 |
|---|---|
| 会话标识 | Cookie `afterlight_sid`（HttpOnly + SameSite=Lax + Secure），服务端签发 `sess_` 前缀随机 ID |
| 会话记录 | 新表 `visitor_sessions`（id / created_at / last_seen_at / ai_experience_used） |
| 影展归属 | 迁移 10：`exhibitions` 增加 `session_id`（NULL = 公共内容或本机）与 `expires_at` |
| 访问校验 | 列表只显示本会话影展；单影展页/写操作校验归属，不匹配返回 404 |
| 公共影展 | 无（作者确认：公网站不放公共影展，首页只有创建入口和本会话影展） |

## 2. 过期清理（1 小时，滑动）

- **滑动过期**：每次请求刷新 `last_seen_at`，**最后一次活动 1 小时后**过期（固定过期会把正在做选片门的访客数据清掉，不合理）。
- **惰性清理**：列表/请求时顺带清除过期会话及其影展（成套删除 DB 行 + uploads 文件），不依赖后台定时器。
- **进行中保护**：仍有运行中 AI 工作流的会话不清理（完成或失败后再清）。
- 公网首页提示：「体验数据为临时数据（1 小时），请及时导出保存」。

## 3. AI 额度三层约束

| 层 | 限制 | 默认值（env 可调） |
|---|---|---|
| 会话层 | 每会话 **1 次**真实 AI 体验（= 一个影展的完整 AI 流程：视觉+筛选+主题+叙事） | `AFTERLIGHT_VISITOR_AI_EXPERIENCES=1` |
| 全局层 | 每天最多 **10 次** AI 体验（Asia/Shanghai 日界，防换 Cookie 刷） | `AFTERLIGHT_PUBLIC_DAILY_AI_EXPERIENCES=10` |
| 单影展层 | AI 分析照片 **≤10 张**（超出拒绝启动并提示精选） | `AFTERLIGHT_VISITOR_AI_PHOTOS=10` |

- 计数时机：**首次启动 AI 分析即锁定**会话次数（防失败重试刷额度）；同影展内重试不再消耗。失败不退次数，但同影展可继续重试。
- 保险层：现有全局调用日限（`AI_MAX_CALLS_PER_DAY`）公网建议设 130（10 次 × 最多 13 调用）兜底。
- **最坏日成本估算**：10 次体验 × 约 16K 输入 + 4K 输出 token ≈ **$0.10/天（峰值价）**，空闲时段实际约一半。

## 4. DeepSeek 空闲时段调度

| 项 | 设计 |
|---|---|
| 高峰定义 | 北京时间周一至周五（不含法定节假日）9:00–12:00、14:00–18:00 |
| 空闲 | 其余全部时段（周末、节假日全天、工作日其他时间）|
| 节假日 | env `AI_PEAK_HOLIDAYS=2026-01-01,2026-05-01,...` 日期列表（作者每年维护）；未配置按普通工作日保守处理 |
| 拦截点 | 仅拦「新 AI 体验启动」；已开始影展内的重试放行（不新增体验次数，调用仍在日限内） |
| 用户提醒 | 创建页/素材页显示一句话状态：「当前为 DeepSeek 空闲时段，可体验真实 AI 策展」/「高峰时段（工作日 9–12、14–18）AI 体验暂不可用，约 xx:xx 恢复」|
| 连接测试 | 公网隐藏/拒绝（作者功能，防止访客探测消耗） |

## 5. 写守卫重构（关键安全点）

| 模式 | 守卫 | 行为 |
|---|---|---|
| 本机版（默认，不设 env） | 现有 `assertLocalMutation` | 完全不变（回环同源），现有 16 项守卫测试保持 |
| 公网完整版（`AFTERLIGHT_PUBLIC=1`） | 新增 `assertVisitorMutation` | 校验 Origin 同源（公网域名，防 CSRF）+ 会话 Cookie + 影展归属 |
| 导出豁免 | 导出不改数据、不调模型 | 公网按「会话归属或公共影展」放行，访客可下载自己影展的离线 HTML/JSON；跨会话导出仍 403 |

## 6. 公网首页与体验动线

```
首页：产品介绍 + 「开始策展」（访客可用）+「在线影展」（公共 2 场，只读）+「我的影展」（本会话，折叠）
创建 → 上传（≤60 张/单张 25MB）→ AI 体验检查（剩余次数/照片数/时段）→ 分析 → 选片门 → 主题门 → 叙事 → 放映 → 导出
AI 用完后：可继续创建影展使用本地演示规则（不限次），界面明确标注「演示模式（未接入真实模型）」
```

## 7. 磁盘与滥用防护

- 平台磁盘 512MB：单会话上传总量 ≤60MB（超出拒收）；过期清理自动回收。
- 最坏情况（1 小时内 10 个新会话 × 60MB）= 600MB 超 disk——叠加日限 10 次体验 + 磁盘水位拒绝（>80% 时新上传拒收并提示稍后再试）。
- 照片/EXIF/文字仍按数据处理，不改变权限（现有原则不变）。

## 8. 已知取舍（作者需知情）

1. **换 Cookie 可再获得 1 次体验**——但全局日限 10 次/天是总闸，刷穿后全网当日无 AI。这是无登录架构下的最优平衡。
2. **平台重启清空一切访客数据**——Qoder Sites 的 $DATA_DIR 本来就是临时的，双重过期保险；对"临时体验"定位无损害。
3. **节假日表每年人工维护**——未维护时按普通工作日保守拒绝（宁可少服务不超支）。
4. **公共影展的展示原片为降采样 2560px 版**——公网带宽与磁盘优化，访客导出的也是该版本；你的本机原图不受影响。
5. **1GB 内存单实例**——并发突发可能变慢，属平台限制；影展数据量小（每会话 ≤10 张 AI 分析）影响有限。
