# 【LifeHack】留影 Afterlight：把散落的照片，策展成一场有叙事的影展

> 曝光之后，光还留在底片上，那叫余晖（afterlight）。
> 快门按下之后，故事还留在照片里——它们值得一场真正的影展。

## 一、自我介绍

大家好，我是 **Captainlidong**，一名在校学生，也是一名摄影爱好者。从第一次按下快门到现在，硬盘里的照片越攒越多，但真正被认真整理、讲完一个故事的很少——大部分照片都在文件夹里"躺平"。这一次，我想用 AI 把"选片难、整理难、叙事更难"这件事彻底解决掉，于是有了这个作品：**留影 Afterlight**。

## 二、作品是什么

**留影 Afterlight 是一个"个人摄影叙事策展智能体"**：上传一组照片，AI 真实地逐张"看图"，给出选片建议、提炼主题、搭出章节化叙事，最终生成一场可以在线放映的摄影影展。

一句话概括：**把一组散乱的照片，变成一场有主题、有章节、有顺序的影展。**

它能做的事：

| 能力 | 说明 |
|---|---|
| 📷 AI 逐张看图 | 接入 DeepSeek 视觉模型，真实理解每张照片的画面内容，输出画面描述与质量分析 |
| 🎯 推荐选片 | 每张照片给出"必留（must_keep）/ 候选（keep）/ 不选"建议，并说明推荐理由 |
| 🧭 主题提炼 | 在整组照片中提炼贯穿性的主题，供你确认或修改 |
| 📖 章节叙事 | 按主题生成章节结构，每章有标题与导语，照片归入各章形成叙事顺序 |
| 🎬 在线放映 | 影展以"放映"形式沉浸式浏览，支持导出离线保存 |

创作工作台全貌：一次影展创作要经过「素材整理 → AI 分析 → 推荐选片 → 主题提炼 → 章节叙事 → 放映导出」六道工序，AI 在每一道工序给出建议，而所有关键决定都等你亲手确认。

比"能做什么"更重要的是**它不做什么**——三条贯穿始终的设计原则：

1. **人是策展人，AI 只是助理。** 整个流程设了两道确认门：AI 的选片建议要你确认后才生效，影展放映也要你最终确认。AI 的每一个建议都只是建议。
2. **你的作品不可被破坏。** AI 生成的所有新版本都不会覆盖你手动编辑过的内容，任何改动可以回退；你编辑期间 AI 不会"抢笔"。
3. **没有额度也能体验完整流程。** 内置 Demo 模式，不消耗任何 AI 资源就能走完"上传 → 分析 → 选片 → 叙事 → 放映"全流程。

## 三、为什么做

每次旅拍回来，几百张照片躺在硬盘里：发朋友圈最多九宫格，放进相册软件只是一堆缩略图。可照片之间本来是有故事的——出发、路上、抵达、黄昏、返程——只是没有一个工具帮我把这个故事"策"出来。

市面上的工具要么帮你修图，要么帮你按时间地点归类，却很少有人帮你**叙事**。而"叙事"恰恰是摄影最打动人的部分：同一组照片，有没有主题、有没有章节、有没有顺序，观感天差地别。

所以我想做这么一个东西：**AI 帮我看图、推荐选片、搭叙事骨架，但每一张照片的去留、每一章的顺序，最终由我决定。** 这也是我对"AI 时代创作者工具"的一次回答：AI 不替你创作，它把创作的完成度从 60% 推到 95%，最后那 5% 的决定权永远在你手里。

## 四、怎么用（5 步）

1. **进入创作层**：打开展示站 [https://afterlight-7t02u8l5rdv.qoder.zone](https://afterlight-7t02u8l5rdv.qoder.zone)，点击「创作影展」进入创作页面；
2. **上传照片**：拖拽或点选上传一组照片（公网体验单场影展最多 10 张，支持批量上传）；
3. **AI 分析**：选择「AI 模式」并勾选授权 → 点击「分析照片」，AI 逐张看图（真实 DeepSeek 视觉模型，非预设结果）；
4. **确认选片**：查看 AI 推荐结果（必留 / 候选 + 每张的理由），调整后确认——这是第一道确认门；
5. **生成并放映**：AI 提炼主题、生成章节叙事 → 预览放映效果 → 确认放映——第二道确认门，你的影展正式"开演"，还支持导出离线保存。

**使用提示（重要）：**

- 真实 AI 体验仅限 DeepSeek 空闲时段开放：北京时间工作日 9:00–12:00、14:00–18:00 为高峰时段暂不可用，其余时段（含周末与法定节假日全天）均可体验；**大赛评审期 2026-12-01 ~ 12-07 已开启全天候开放**，随时可体验；
- 每位访客有 1 次真实 AI 策展体验机会（全站每天 10 次，先到先得）；额度用尽或高峰时段可体验 Demo 模式，流程完全一致；
- 公网采用匿名会话：无需注册登录，影展数据 1 小时后自动过期清除，不留存任何访客照片。

## 五、怎么用 Qoder 做出来的

整个项目从第一行代码到部署上线，**全程在 Qoder 里以 AI 协作方式完成**：我负责提出需求、把关验收、跑真实测试，Qoder 负责把想法变成代码、写测试、修 bug。

技术栈：Next.js 16（App Router 全栈）+ Node.js 内置 SQLite + sharp 图像处理 + SWR + Zod + DeepSeek API（视觉 + 文本双模型）。

我的开发方法（也是这次比赛最大的收获）：

1. **先拆阶段，再动手。** 我把"摄影策展"拆成六个阶段：素材整理 → AI 分析 → 推荐选片 → 主题提炼 → 叙事生成 → 放映导出，每个阶段单独提出需求、单独验收，绝不"一口气全要"。
2. **需求说人话，细节说到位。** 在 Qoder 里用自然语言描述产品行为，比如"普通 keep 是候选，must_keep 必须保留""用户编辑过的部分 AI 不能覆盖""AI 每次外发照片前必须获得我的授权"——细节说得越清楚，生成的代码越贴合想要的东西。
3. **真实数据验收，拒绝模拟糊弄。** 我用自己的真实照片 + 真实 DeepSeek API 做了两轮验证（3 张小样、14 张扩大样本），逐张对照 AI 输出与原图，确认画面描述零编造。
4. **真实部署，真刀真枪。** 展示层部署到 Qoder Sites 开放公网访问，创作层部署在自己的腾讯云服务器上（systemd 守护 + 防火墙 + 内存优化），每一步都在 Qoder 的协作下完成。
5. **踩坑也是开发的一部分。** HTTP 环境下浏览器 API 兼容、大图上传限制、服务器内存不足导致的假死……每一个真实问题都在 Qoder 里定位、修复、回归测试。
