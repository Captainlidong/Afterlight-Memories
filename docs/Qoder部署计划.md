## 1. 项目背景

「留影 Afterlight」是 2026 Qoder 高校创造力大赛参赛作品：一个个人摄影叙事策展智能体。访客上传一组照片后，系统经过素材管家 → 审美筛选官 → 主题发现官 → 叙事编剧 → 布局设计师 → 策展质检官六道工序，生成一场可放映、可导出的个人影展。

技术形态：Next.js 全栈应用。因作品含实时 AI 代理、SQLite 数据库与图片处理（sharp）等长驻服务能力，经架构决策采用**前后端分离部署**：

| 层 | 承载平台 | 内容 | 谁来部署 |
|---|---|---|---|
| **静态展示层** | **Qoder Sites**（本文档的任务） | 落地页 + 示例影展完整可玩版 | **Qoder（本次任务）** |
| **实时创作层** | 作者自有腾讯云服务器（IP 从略，不入公开仓库） | 完整创作流程：上传 → 真实 AI 策展（DeepSeek，受每日额度约束）→ 放映 → 导出 | **已部署运行中**（2026-11-22 完成并实测），无需 Qoder 处理 |
| **作品帖** | 天池赛题页论坛 | 自我介绍 / 作品是什么 / 为什么做 / 怎么用 / 怎么用 Qoder 做的 + Qoder 账号 | 作者撰写 |

## 2. Qoder 需要执行的任务：部署静态展示层

### 2.1 部署物（共 2 个文件，纯静态、无需构建、无需环境变量、无需密钥）

| 文件 | 大小 | 说明 |
|---|---|---|
| `index.html` | ~5KB | 产品落地页：作品介绍 + 两个入口卡片 + 体验说明 |
| `demo-exhibition.html` | ~3MB | 示例影展「在光线转弯之前」的完整可玩版：24 张照片、三章节叙事、影院式放映控件。**完全自包含**（全部图片以 base64 内嵌，无任何外部请求），断网也能完整放映 |

### 2.2 部署要求

- 使用 Qoder 的 Sites 功能进行**纯静态托管**（不需要 Functions、数据库、对象存储、环境变量或任何 Secrets）
- 托管后评委/访客通过 Qoder Sites 公网链接点开即可访问（满足大赛提交清单第一条）
- `index.html` 中有一个跳转卡片指向作者自有服务器的创作入口（直链地址从略，服务器 IP 不入公开仓库），这是预期行为，**不是待修复的外链**——该服务器承载实时创作流程，由作者自管

### 2.3 部署后验收标准（Qoder 完成后请自查，作者也会复核）

1. 公网链接打开 → 落地页正常渲染（暗色影院风格、两张入口卡片可见）
2. 点击「观看示例影展」卡片 → 进入 `demo-exhibition.html`，放映控件可见，可逐张滚动浏览 24 张照片
3. 落地页的「开始创作我的影展」卡片 → 新窗口打开作者服务器的创作入口（**已部署运行中**，点开应看到「开始策展」页面）
4. 浏览器控制台无报错

## 3. 明确不在 Qoder 任务范围内的事项

- **不涉及任何密钥/Secrets**：静态层无 API 密钥；实时 AI 的 DeepSeek 密钥仅存在于作者自有服务器的环境变量中
- **不需要**在 Qoder Sites 上配置 Functions、数据库、对象存储
- **不要**修改或重新部署作者自有服务器上的创作层
- 落地页中指向作者服务器（IP:3000）的链接为设计意图，不要移除或改写

## 4. 架构说明（供 Qoder 理解上下文）

- **为什么静态层与创作层分离**：创作层含实时 AI 代理（DeepSeek，付费接口）、SQLite 数据库与图片处理等长驻服务能力，适合运行在作者自有服务器上并施加每访客 1 次、每日 10 次、单影展 10 张照片的额度约束；静态展示层无任何后端依赖，适合 Qoder Sites 托管。两层职责清晰，访客隐私（会话隔离、数据 1 小时过期）由创作层的匿名会话机制保证。**创作层当前已在作者服务器上运行（systemd 开机自启），并已完成「上传 → 真实 DeepSeek 策展 → 确认门 → 放映 → 导出」全链路实测。**
- **示例影展为什么能离线放映**：作品内置「离线导出」能力，可把一场影展导出为单文件自包含 HTML（图片内嵌、放映脚本内置）——Qoder Sites 上的 `demo-exhibition.html` 正是这一能力的产物。
