## 2. 你需要准备什么

在服务商控制台获取：

| 字段 | 说明 |
|---|---|
| `AI_BASE_URL` | 服务商给出的 API 接口地址，通常以 `/v1` 结尾。程序固定拼接 `/chat/completions`。非本机服务必须 HTTPS。 |
| `AI_API_KEY` | 服务商密钥。只写在服务端 `.env.local`。 |
| `AI_VISION_MODEL` | 多模态模型 ID（能接收图片 + 文本）。 |
| `AI_TEXT_MODEL` | 纯文本模型 ID，可选；留空时复用视觉模型。 |

本项目只支持 **OpenAI 兼容协议**（`AI_PROVIDER=openai-compatible`），不内置任何特定服务商 SDK。

## 3. 配置步骤

1. 复制项目根目录的 `.env.example` 为 `.env.local`（`.env.local` 已在 .gitignore 中，不会进入版本控制）。
2. 填写上述字段，并确认 `AFTERLIGHT_MODE` 与预算相关数值。
3. 重启服务：

   ```text
   # 开发模式
   Ctrl+C 停止后：npm run dev
   # 生产模式
   npm run build && npm start
   ```

4. 在创建页或素材页展开「AI 使用说明与连接状态」。加载和「重新加载状态」只读本地配置/记录，不调用模型；页面不提供密钥、服务商地址或预算输入框。无配置、配置无效时连接测试禁用，仍可创建影展和上传照片。
5. 配置完整不代表密钥有效。连接测试必须先单独勾选确认，再点击「测试模型连接」；每次重试都重新确认。固定文字 + 服务端内存生成的 16×16 纯色 JPEG，最多 **2 次请求**，不使用个人照片/EXIF/路径，不做自动重试或格式修复。鉴权、预算或配额等错误可提前停止第二项。
6. 文本和视觉分别展示结果，文字成功不等于视觉可用，两个探测通过也不保证真实照片质量或后续生成成功。状态只认可当前配置、同一次测试的结果，不拼接历史成功；更改配置并重启后须重新测试。本次点击被预算拒绝会显示失败，不沿用旧成功；重新加载则展示最近有调用记录的测试及其时间。
7. 连接测试确认**不等于授权影展照片外发**。素材页切换 AI 后仍需显式勾选压缩分析图与必要文字的处理授权，再点击分析。生成过程中可撤销，后续请求检查最新授权；无法收回已发送的数据。切换模式会取消旧授权和选片确认、使分析过期，需重新分析并确认，不删除旧作品。

默认 `npm run dev` / `npm start` 绑定 `127.0.0.1`。所有 API 写请求仅接受本机同源页面；跨域、缺少 Origin、外部代理链或 `AFTERLIGHT_ACCESS_MODE=public` 被拒绝。用浏览器从本机地址操作，脚本调用也需正确同源头；这不是公网认证方案，勿改为对公网监听。

### 3.1 DeepSeek 本地比赛配置

2026-11-20 核对官方 [视觉说明](https://api-docs.deepseek.com/guides/vision) 与 [思考模式](https://api-docs.deepseek.com/guides/thinking_mode)：`deepseek-flash` 支持现有 `image_url` Base64 JPEG 输入，可同时用于视觉和文本；不能把仅支持文本的模型当作视觉模型。模型可用性以账户实际权限为准，文档兼容不等于真实联调通过。

在本机 `.env.local` 填写下列字段；已有文件只改对应项，不覆盖其他配置，`AI_API_KEY` 的空值由作者本机填写，不发到聊天：

```dotenv
AFTERLIGHT_ACCESS_MODE=local
AFTERLIGHT_MODE=demo
AI_PROVIDER=openai-compatible
AI_BASE_URL=https://api.deepseek.com
AI_API_KEY=
AI_VISION_MODEL=deepseek-flash
AI_TEXT_MODEL=deepseek-flash
AI_MAX_RETRIES=0
```

- 保持首页默认 Demo，在新影展中手动选 AI，不会自动发送原有照片；文本模型也可留空，复用视觉模型。
- 官方主机 `api.deepseek.com` 的所有模型请求显式传 `thinking: { type: "disabled" }`，避免默认思考过程影响短探测和结构化输出；其他兼容服务不添加该参数，第三方代理也不按模型名称猜协议。连接探测仍各 32 个输出 token、最多两次且不重试。
- 模型地址不含 `/chat/completions`；密钥使用项目已有变量 `AI_API_KEY`，不要误填成 `DEEPSEEK_API_KEY` 或 `NEXT_PUBLIC_*`。
- 首轮关闭自动重试便于核对费用；仍需在真实调用前按第 5、6 节约定照片和总次数，保留既有任务/日预算。3 张照片正常首次全流程需要 6 次业务请求（逐图 3 次 + 选片/主题/叙事各 1 次），加一次完整连接测试共 8 次；这是无失败、无重新生成的估算，不是自动外发授权。
- 停止旧服务后依次构建、启动，先在页面单独确认固定连接测试，再按已确认照片范围授权完整流程。实际验收应包含选片确认、选主题、叙事/布局/质检、人工编辑、浏览与导出，不能只用文字探测成功代替完整功能成功。

## 4. 安全与隐私边界（必须遵守的设计约束）

- 密钥只从服务端环境读取；**禁止** `NEXT_PUBLIC_*`、前端输入、localStorage、URL、导出文件或日志中出现密钥。
- 外发前每次检查数据库里的最新授权（`allow_external_ai`）；撤销授权后停止后续外发。已发送的数据无法通过本地撤销收回。
- 只发送**压缩后的分析副本**（按 EXIF 转正、限制长边、去元数据）与必要文字；原图留在本地；默认不发送 GPS/完整 EXIF/本地路径。
- 分析副本固定 JPEG，长边由 `AI_IMAGE_MAX_EDGE` 控制（默认 1280），内部上限 1MB；超出 4000 万输入像素、损坏或不支持的格式会逐张拒绝，不自动放大图片。
- 分析副本仅在服务端内存中存在，转为 Base64 图片消息发送；不落盘、不写数据库或日志，只保存副本 SHA-256 用于缓存和审计。授权撤销、配置缺失、预算/配额不足会中止后续外发；单张坏图或非法模型响应会明确标记失败，已校验成功的结果保留但整批不会假报完成。
- 模型返回文本按普通文本渲染；模型无执行命令、浏览 URL、访问本地文件的权限（不开放工具）。
- 调用计数是次数上限，不是金额上限；请在服务商控制台同时配置余额/额度限制。
- V21 复验脚本为 `scripts/stage-g-security-check.mjs`（Windows Chrome / Node 24），使用临时假密钥、本机 Mock 和全新隔离库，不依赖真实 Key。须先停止本项目 dev/start，再执行 `node scripts/stage-g-security-check.mjs --production-stopped`；它会重建 `.next`，结束后须正常 `npm run build && npm start` 恢复原服务，切勿并行共享构建目录。结果与未测范围见 `v3-acceptance.md`。

## 5. 费用控制

- `AI_MAX_CALLS_PER_JOB`（默认 40）现按**同一影展的持久策展任务**累计：分析、确认后的主题/叙事、重试、重新生成与重新分析共用额度，跨日、重启、模式切换、revision 变化均不重置。首次 AI workflow（或首次有效业务预留）冻结上限；调高配置不能扩额，调低可进一步限制。暂无同影展重置额度或新轮次入口，也不要通过新建影展/换库绕过作者授权。
- `AI_MAX_CALLS_PER_DAY`（默认 100）仍是所有模型请求共用的全局日上限，含连接探测、重试和格式修复。每次业务外发原子预留任务总额与日额；已发送、失败或超时都占额，只有尚未发送的 reserved 可原子退还，已退还的预留不能再发送。
- 升级保留历史调用记录，并把该影展此前非 released 的业务记录纳入首次任务计数。旧 reserved 后续释放可能仍被保守计入任务总额，不自动补发额度；连接探测不计业务任务额。workflow 保存照片 ID/revision 快照，已绑定工作流在输入范围变化后不得继续外发；这不是对所有历史分析内容的完整溯源保证。
- 小样联调必须先取得作者的总次数 N，再在全新隔离数据目录中显式设置 `AI_MAX_CALLS_PER_DAY=N`。同一数据库、同一应用进程、固定时区且仅在该时区同一自然日内执行，避开午夜；不换库、不清计数、不调高上限、不并行启动恢复进程。缺省/空值会回到默认 100，不可留空。测试结束撤销授权并停止测试服务，跨日需要重新确认剩余额度，不能靠日额自动重置延长授权。
- 单日小样还应在首次 AI workflow 前明确设置任务额度（业务部分不大于总授权 N）。持久任务额不覆盖连接探测，不能替代包含探测的跨日总授权账本；跨日或追加照片/探测仍须核对剩余授权，不能默认继续。尚未提供范围前只运行本地 Mock。
- 单图视觉缓存现在可在同影展内跨 workflow 和重启复用，受图片实际输入、服务配置、模型、提示词/schema/预处理版本及有效请求参数约束；文本缓存仍沿用 workflow 范围。复用会重查授权、照片归属、任务状态并重新校验结果，不跨影展共享。并发请求合并限同进程、同 DatabaseSync 对象、同 transport 和相同有效请求；不同输入不合并。关闭缓存、无 cacheKey 或连接探测不合并；没有跨进程合并。实际 HTTP 并发限制另在服务配置共享队列执行，不依赖合并是否命中。
- 超时/中断的请求保守占用名额（服务商可能已计费），不会把未知结果记成 0。
- 缓存命中、轮询、播放、导出不产生新调用。
- 连接测试计入全局日预算以及 `AI_CONNECTION_TEST_LIMIT_PER_HOUR` 小时额度；额度按请求数而非点击数计算，一次完整测试占两次。超出额度不会自动重试。
- 分析成功的每张结果立即保存，界面显示「已保存分析 X/N」，包含以前保留的结果而非本轮完成百分比。显式重试会重新检查输入，可能重访成功照片并继续消耗同一影展任务剩余额度，不承诺只重发失败照片。

## 6. 真实联调前必须确认（作者）

开始外发真实照片前，请明确告诉我：

1. 选择哪些照片（第一轮建议 3–5 张非示例照片，确认无误后再扩到 12–20 张）；
2. 发往哪个服务商（Base URL / 模型 ID）；
3. 最多允许多少次调用。

我会据此先做最小范围联调，并在脱敏的调用记录里核对 usage 与结果，再进入真实质量审阅。未经你确认范围，我不会自动上传你的私人照片。
